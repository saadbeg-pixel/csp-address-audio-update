Partner App · Booking decision screen · Design update

Address audio & पता नहीं समझ आया?

Three changes to the screen where a partner decides on a new booking: a new audio address player, one entry point for help with the address (in place of two), and tighter spacing so the card fits the new structure.

At a glance

What changes

01 · Audio

New voice-note player

A chat-bubble player: play/pause, a full-width waveform, the duration and a customer avatar. The पता समझें label goes.

02 · Entry point

One link, two options

The पता नहीं समझे? link and the nearby-connections row become one link. It opens a sheet: call the customer, or see your nearby connections.

03 · Spacing

Tighter card

Gaps inside the address card get smaller, and the nearby row leaves the card. The new values are marked in Figma and listed below.

Where this applies. The card is one composable, BookingFpnOverlay. It is rendered in two places, and both get the change: the booking FPN (MainActivity) and the booking drilldown (BookingFlowContent). The call sheet and the nearby-connections sheet stay as they are. Only the way you reach them changes.

Change 01

Audio address player

The player now looks like a voice note from the customer. Before, it was a small play button, the पता समझें label and a 12-bar waveform pushed to the right. Now it is one tinted bubble that runs the full width of the card.

States

  • Idle: play icon, all bars grey, total duration.
  • Playing: pause icon, bars fill pink left to right with progress.
  • Paused: play icon, the pink fill stays where it stopped.
  • Finished: rewinds to Idle. This matches today's behaviour.
  • No recording: the bubble is not shown at all, as today. The link sits 16dp under the address.
  • Loading / failed to load: not designed yet. See the open questions.

Tracking does not change: address_audio_played still fires on play.

Change 02

One entry point: पता नहीं समझ आया ?

The card used to offer two separate ways to work out an address. The पता नहीं समझे? link opened the call sheet. A bordered row, यहाँ आपके पहले से 3 कनेक्शन लगे हैं, opened the nearby-connections sheet. Both solve the same problem, so they now sit behind one link. The nearby row is removed from the card.

पता नहीं समझ आया ?→ Sheet · पता समझें→ Call sheet or Nearby sheet

The link

  • Copy पता नहीं समझ आया ? (was पता नहीं समझे ?).
  • Label/L2_14_Regular 14/20 · brand #D9008D · no underline · left-aligned. Before, it was bodyMd in textSecondary with an underline.
  • Sits 16dp below the address block and is the last item in the card.

New sheet: पता समझें

  • Sheet: bg bg/default · top radius 24 · drag handle 36×4 stroke/subtle (handle row 12 top, 8 bottom) · content 12 top, 24 bottom, 16 sides. There is no CTA. It closes on drag, scrim tap or system back.
  • Title: पता समझें · type/heading/lg 24/32 Bold · 16dp to the list.
  • Rows: DS List Item, Type=Default · min-height 48 · padding 16 · gap 12 · 24dp leading icon · 20dp chevron on the right in brand · 1dp divider between rows.
Row 1 · call

कस्टमर से पता कॉल पर समझें

Opens the existing call sheet, AddressUnclearSheet, with the IVR call and the code chip. Same behaviour as today's link.

Row 2 · nearby

पहले से लगे अपने {count} कनेक्शन देखें

Opens the existing NearbyConnectionsSheet (map + list). Same behaviour as today's nearby row. {count} is the existing nearbyConnectionsCount.

When a row can't be shown

  • Today the nearby sheet opens only when there are connections and the booking has map coordinates. Under the same conditions, Row 2 is hidden when the count is 0 or the booking has no lat/lng.
  • Row 1 is always available. If the booking has no IVR code, the call sheet hides the code chip, as it does today.

The two sheets it opens

The layouts don't change. One copy difference: the Figma call-sheet CTA reads कस्टमर से बात करें, while the live string is कस्टमर से बात करवाएँ. See the copy table.

Before build

Open questions

Figma doesn't settle these. Each has a suggested default so build doesn't stall, but please confirm.

  1. Does the install drilldown get the new player too?The player (AddressVoiceNote) is shared with the install drilldown, deliberately, so the two can't drift. The Figma only shows the booking card.Restyle the shared component so both surfaces get it.
  2. Where does "back" go from the call or nearby sheet?From वापस जाएँ / ठीक है / system back, it could go to the पता समझें sheet or straight to the booking card.Straight to the booking card. One level of sheets, and the link is one tap away.
  3. When Row 2 is hidden, show a one-row sheet?With no nearby connections, the chooser would hold only the call option.Skip the chooser. The link opens the call sheet directly, as it does today.
  4. Duration: total or countdown while playing?The playing frame still shows 0:45. Today the player counts down.Count down while playing (elapsed shown as fill), and show the total when idle.
  5. कस्टमर से बात करें or करवाएँ?The Figma CTA differs from the live string. It may be a deliberate change or drift in the file.
  6. Tap target for play.Only the 24dp icon, or the whole bubble?The whole bubble toggles play/pause. 24dp is below the 48dp touch minimum.
  7. Loading and error states for the audio.The stream is prepared after the first tap, which can take a moment on a weak network. No state is designed for that or for a failed load.
  8. New tracking?Opening the पता समझें sheet and choosing a row are not tracked today. Should they be, to see which option partners use?

Inconsistencies spotted in the Figma

  • The two rows in the पता समझें sheet use different text styles. Row 1 is type/body/lg 16/24 and Row 2 is L2_14_Regular 14/20. One of them is probably unintended.
  • Row 1 has the same text as the call sheet's title, so the partner reads the same line twice in a row.
